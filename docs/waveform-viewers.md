# ngscopeclient and PulseView

Use these viewers for interactive analysis of ScopeLoop's saved evidence.
ScopeLoop retains acquisition ownership, settings and raw artifacts; exported
files let a human inspect the same capture without another instrument connection.

```sh
scopeloop evidence export capture-bundle viewer-files
# Raise the expansion budget deliberately for longer digital recordings:
scopeloop evidence export capture-bundle viewer-files-long --max-samples 100000000
```

MCP `scopeloop_evidence_export` takes `bundle`, `output`, and optional
`max_samples`. Paths are on the MCP host. No instrument configuration or connection
is needed. Copy the resulting directory to the workstation running the viewer.
The operation verifies the source status and artifact hashes, requires a new output
directory outside the source bundle, and preserves the original evidence.

## ngscopeclient

Open **Add > Import > CSV** and select `analog-ngscopeclient.csv` or
`digital-ngscopeclient.csv`. Set the X unit to seconds and analog Y units to volts.
Use its waveform views and filter graph for cursors, spectra and further analysis.
The exported first column retains the original seconds, including negative
trigger-relative time. Digital exports preserve sparse transition rows.

The [upstream CSV importer](https://github.com/ngscopeclient/scopehal/blob/master/scopeprotocols/CSVImportFilter.cpp)
distinguishes analog from digital by numeric spelling. ScopeLoop writes analog
values in exponential notation, including zero and one, to avoid accidental digital
classification. Labels containing CSV delimiters/control characters are sanitized;
`export.json` records both original and exported labels. No quoted-field parser is
assumed. See the [official manual](https://www.ngscopeclient.org/manual/Filters.html)
for import and analysis options.

## PulseView and sigrok-cli

Open `analog-pulseview.sr` or `digital-pulseview.sr` in PulseView, or launch:

```sh
pulseview -D -i viewer-files/digital-pulseview.sr
sigrok-cli -i viewer-files/digital-pulseview.sr -O csv
```

`-D` prevents PulseView auto-scanning hardware. Add protocol decoders in PulseView
and assign the exported channels. For automated saved-file decoding, use the real
`sigrok-cli` and a supported decoder, for example
`sigrok-cli -i digital-pulseview.sr -P uart:rx=RX:baudrate=115200` when the channel
is named RX. Record decoder settings and version alongside any derived result.

ScopeLoop writes the native version-2 session archive described by the
[libsigrok writer](https://github.com/sigrokproject/libsigrok/blob/master/src/output/srzip.c)
and [reader](https://github.com/sigrokproject/libsigrok/blob/master/src/session_file.c).
Each sample rate has a separate file. Analog samples are float32; digital samples
are bit-packed with held states expanded on the original sample grid, including
the final observed row. The default maximum is 50 million samples per stream,
written in bounded chunks. Nonuniform analog data, off-grid transitions, missing
channels, invalid values and excessive expansion are rejected.

PulseView starts these files at zero: add `time_origin_s` from `export.json` to
recover original timestamps. Do not feed Saleae's sparse digital CSV directly to a
uniform CSV importer; that changes event timing. Requested capture duration is not
used to invent a final hold. A one-row CSV cannot establish a time span and fails.

## Validation and limits

The export directory includes source manifest, original artifact hashes, labels,
sample rate, observed time span, sample count and SHA-256 checksums. Source probing,
coupling, clipping and qualification limits still apply. Both viewers use float32
analog amplitudes internally; original float64 NPZ/CSV evidence remains available.
The final displayed sample interval is a viewer convention beyond the last observed
timestamp, not proof of an additional observation.

Independent synthetic analog and 10-channel digital fixtures were read through
libsigrok, checking samples, labels, rates, multi-byte packing and sparse hold timing.
Windows PulseView's libsigrok 0.6.0-git-0bc2487 read and cleaned up all fixtures
successfully. Linux libsigrok 0.5.2 read the analog values correctly but aborted
during cleanup; files generated by its own srzip writer reproduced that defect.
Use the newer validated desktop runtime for analog viewing. ngscopeclient's CSV
format was checked against upstream source; a GUI import is not yet validated.

The older `instruments/sigrok.py` adapter uses `pysigrok-cli` and is experimental;
it is separate from this tested export path and the upstream `sigrok-cli` program.
The optional dependency alone does not establish reliable capture, decoding or
PulseView integration. Direct ngscopeclient/PulseView hardware control requires an
explicit bench handoff because third-party tools do not honor ScopeLoop's leases.
